## How I approach engineering

- **Start with the operational problem.** The data model and workflow should reflect how the system is actually used.
- **Keep state ownership explicit.** This matters in real-time systems, backend workflows, and frontend architecture alike.
- **Automate repetitive coordination.** Good internal software removes duplicate entry, manual reconciliation, and status chasing.
- **Understand the abstraction below the abstraction.** Systems work in C/C++ and custom runtime experiments informs how I reason about higher-level application code.
- **Ship something verifiable.** Deployed applications, documented architecture, tests, and readable repositories matter more than technology lists.
